# Копии обеих баз на Windows

Это ручное скачивание после входа в панели. На выключенный компьютер сайт сам копии не отправляет.

1. Откройте https://recordirk.ru/#admin под владельцем. Нажмите «Скачать копию сейчас».
2. Откройте https://www.cf-baza.ru/admin/backups под администратором. Нажмите «Скачать копию CF BAZA».
3. Сохраните оба файла `.json.gz` в личную папку, например `Документы\SiteBackups\2026-11-10`.
4. Проверяйте наличие свежих файлов регулярно и перед крупными изменениями. Храните несколько дат, а также отдельную копию на отключаемом накопителе.

Сжатие gzip не шифрует данные. Файлы содержат персональные данные: используйте защищённую учётную запись Windows и шифрование диска, не отправляйте файлы в общие чаты.

Необязательный помощник: [tools/backup-windows.ps1](../tools/backup-windows.ps1). Скачайте его через Raw → «Сохранить как». Запустите в PowerShell из папки со скриптом: `& .\backup-windows.ps1`.
Он откроет обе панели, дождётся скачиваний, проверит формат gzip/JSON, скопирует свежие файлы из стандартной папки Downloads в `Документы\SiteBackups\<дата-время>` и сравнит SHA256. Исходные файлы не удаляются. Если браузер сохраняет в другую папку или Windows запрещает запуск скриптов, используйте ручные шаги выше; менять политику выполнения не требуется.

## Что входит в копии

- RECORDIRK: контент, пользователи, дети и связи со взрослыми, заявки, команды, результаты, согласия и служебные справочники. Ежедневные серверные копии дополнительно сохраняются внутри `record` 14 дней.
- CF BAZA: настройки, контент, фотографии, заявки, CRM, тренировки, атлеты и отметки. Снимок создаётся при скачивании в согласованной транзакции. Отдельное автоматическое хранение копий `cfbaza` на сервере этим изменением не включается.

## Восстановление

Каждая копия относится только к своему приложению и базе. Для восстановления предназначены `tools/restore.js` соответствующего репозитория. Восстановление полностью заменяет данные выбранной базы; сначала используйте отдельную тестовую базу с актуальной схемой.

Команды требуют явного `RESTORE_CONFIRM=record-site` или `RESTORE_CONFIRM=cfbaza-site`, пути к файлу и `DATABASE_URL` целевой базы. Неполная копия отклоняется до удаления данных; ошибка записи откатывает транзакцию. Восстановление не запускается при старте сайта или деплое.

Рабочие базы при подготовке этих исправлений не восстанавливались. Тестовое восстановление выполнялось только на синтетических данных в отдельном PostgreSQL.
